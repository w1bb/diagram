# Maintain Frontend Structure

Implement frontend changes without weakening repository boundaries or introducing hidden dependencies.

## Start with the contract

1. Read `docs/architecture.md`, the active record in `docs/changes/`, `frontend/package.json`, and the nearest related source files.
2. Inspect the full worktree and preserve unrelated changes.
3. Treat the existing package manifest as a closed set. Never run `npm install`, `npm add`, `npx`, `pnpm`, `yarn`, or another package-fetch/install command for frontend work. Never add a package or lockfile. If a request appears to require one, use React or a browser API; otherwise report the conflict.
4. Keep Source Sans 3 self-hosted under `frontend/src/assets/fonts/`. Do not add a runtime font/CDN request.

## Preserve source boundaries

Place code according to responsibility:

```text
frontend/src/
  api/          transport client, DTOs, and API error mapping
  app/          composition root, providers, and route resolution
  assets/       versioned static assets such as fonts
  components/   dependency-free shared presentation primitives
  features/     domain-focused data, models, components, and pages
  layouts/      application shells and cross-page layout
  pages/        route-level pages not owned by one domain feature
  styles/       fonts, global reset, and color tokens
```

- Keep feature-specific code inside its feature. Promote code to `components/` only after it is genuinely shared.
- Keep server DTOs and transport behavior in `api/`; do not call `fetch` directly from a component.
- Keep fixture data in files named `*.fixture.ts` behind typed access functions. Never mix fixtures into transport code.
- Keep route parsing and navigation in `app/routing`. Use `projectPath` rather than hand-building project URLs.
- Avoid broad barrel exports and dependency cycles. Import the narrow module that owns the symbol.

## Preserve routing behavior

Use the native History API router. Maintain these canonical routes:

- `/`
- `/projects` -> redirect to `/`
- `/projects/:projectId` -> redirect to `/projects/:projectId/requirements`
- `/projects/:projectId/requirements`
- `/projects/:projectId/codebase`
- `/projects/:projectId/report`
- `/projects/:projectId/logs`
- every unmatched path -> visible 404 body

Treat project IDs as opaque path segments and encode/decode them at the route boundary. Intercept only unmodified, primary-button internal link clicks so new tabs, copied links, browser history, and accessibility behavior remain native.

Keep document scroll restoration in `app/routing/RouterProvider`. Every resolved route change must reset the window to the top-left before paint, including programmatic navigation, redirects, and browser back/forward traversal. Keep native `history.scrollRestoration` manual only while the router is mounted and restore its prior setting on cleanup; do not duplicate route-scroll effects in feature pages or reset independent nested scroll regions.

## Preserve styling and interaction rules

- Use a colocated `*.module.css` file for component/page styling. Keep only resets, font faces, and color theme definitions global.
- Define CSS custom properties for colors only in `styles/tokens.css`. Do not introduce spacing, size, typography, duration, or easing variables.
- Reference a color token for every CSS color, background, border, outline, shadow color, and overlay color.
- Keep `box-sizing: border-box` on all elements and pseudo-elements.
- Support explicit light/dark selection plus the system preference. Persist only the theme string in local storage.
- Keep interface icons in `components/icons/Icons.tsx` as small inline React/SVG components using the local shared Lucide wrapper and `currentColor`. Source geometry only from the official Lucide repository revision pinned in `components/icons/README.md`, retain the colocated Lucide/Feather license, and update the component-to-source map when shapes change. Do not add an icon dependency, runtime network request, feature-local icon drawing, sprite, font, or generated wrapper. Purpose-built SVG spinners and data visualizations are not interface icons and remain with their owning components.
- Animate accordions with grid-row expansion and caret rotation. Never animate with `translateY` and never add `translateY` anywhere in frontend styles.
- Keep the desktop project navigation in the local `components/layout/SplitView` primitive. Preserve its bounded pointer and keyboard resizing, accessible separator values, preferred-size reset, zero-width collapse, last-width restoration, focus-transferring reopen control, and dependency-free implementation; do not replace it with a package.
- Build modal features with `components/overlay/Modal`. Preserve its portal, focus trap and restoration, Escape/backdrop dismissal, scroll lock, configurable icon/title/description slots, asymmetric 150/250-millisecond entrance and 100-millisecond exit, scale-only panel motion, and reduced-motion handling.
- Build navigation search with `components/forms/SearchInput`, keep filtering derived from project state, and render an explicit no-match message.
- Build browser file selection mechanics with render-prop `components/forms/FileDropzoneRaw`: preserve its hidden native input, picker trigger, nested drag-depth state, optional drag-active class, matching accept validation for picked and dropped files, single/multiple and disabled behavior, accepted/rejected callbacks, and presentation-free boundary. Compose `components/forms/FileDropzone` as the established styled wrapper with configurable copy/icon/root/button hooks. On Requirements, show the styled wrapper only with zero sources; once populated, compose the raw primitive around the source list with a compact picker action and keep the Requirement set card directly below Source documents at every width. Keep upload and domain state in the consuming feature.
- Render compact navigation counts with `components/data/NumberChip`; use its neutral appearance for contextual totals and strong appearance for attention-bearing row counts instead of duplicating chip CSS in features.
- Render shared indeterminate activity with `components/feedback/Spinner`. Keep its SVG track and rounded arc on `currentColor`, expose a status label when it is the only loading cue, and mark it decorative when adjacent text already communicates the state. In project workflow navigation, replace only an `in-progress` stage number with the spinner and retain the visible status text.
- Derive each project accordion link's trailing workflow indicator from `ProjectSummary.workflowStatuses`: show the shared spinner for `in-progress`, a local checkmark for `ready-for-review`, a local warning icon for `outdated`, and nothing for `complete` or `not-started`. Keep status text available to assistive technology and synchronize the fixtures, session defaults, sidebar links, and workflow cards when changing the status union.
- Keep the three compact cross-page workflow cards in the shared project-owned `ProjectWorkflowNavigation` component and give Requirements, Codebase, and Report a 32-pixel top inset without changing Logs. Center slim 1.5-pixel connectors exactly inside the desktop gaps and between the vertical mobile cards. Own global visible/hidden preference in `ProjectWorkflowNavigationProvider`, default it to visible, persist only `visible` or `hidden` under `implementation-verifier:workflow-navigation-visibility`, and tolerate unavailable local storage. Close the visible workflow through a labeled, borderless local X in an outside card gutter with the same visual weight as the arrows; reopen it through a labeled downward caret centered over the top of the workspace body. Keep that caret out of document flow, animate its `top` position from above the viewport rather than scaling it, and account for the sticky mobile header. Mount and focus it only after the drawer's `grid-template-rows` close transition ends, while rendering it immediately for an initially hidden saved preference. Preserve `aria-expanded`/`aria-controls`, inert and accessibility-hidden collapsed content, counterpart focus transfer, grid-row/opacity/scale drawer motion without `translateY`, global reduced-motion behavior, a stable root scrollbar gutter, and the drawer wrapper's opt-out from scroll anchoring.
- Send transient application feedback through the external `components/feedback/Toast/toastStore` API and render it once with `components/feedback/Toast/ToastProvider` at the composition root. Preserve bottom-center stacking, a maximum of three exposed items, four-second default dismissal, hover/focus pause and resume, explicit close controls, variants, accessible status semantics, responsive actions, and reduced-motion handling. Do not build page-local toast containers or persist toast content.
- Keep the mocked Codebase workflow under `features/codebase` with typed `model/`, `data/*.fixture.ts`, and stateful `hooks/` boundaries. Support multiple HTTPS URL/token drafts, clear raw tokens after the two-second mock validation, lock validated URLs and credentials, and invalidate configuration on add/delete. ## Preserve accessibility

- Use semantic landmarks, headings in order, native links for navigation, and native buttons for disclosure/actions.
- Provide labels for icon-only buttons, `aria-expanded` and `aria-controls` for accordions/drawers, `aria-current="page"` for active routes, and a skip link.
- Maintain visible keyboard focus and do not rely on color alone for essential meaning.
- Render external, uploaded, model-generated, and route-derived content as text; never inject raw HTML.

## Verify without installing

1. Search for new dependency declarations, lockfiles, remote font imports, non-module component styles, hard-coded CSS colors outside `tokens.css`, and `translateY`.
2. Run `npm run typecheck` and `npm run build` only when `frontend/node_modules` already exists. Do not install packages to make validation available.
3. If dependencies are absent, run static repository checks, review TypeScript imports/types carefully, and state explicitly that executable build verification remains pending.
4. Exercise route resolution, redirects, accordion keyboard semantics, mobile navigation, both themes, and the 404 body when a browser environment is available.
5. Update the active change record and architecture documentation with actual results and limitations.
